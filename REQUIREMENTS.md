# Warcraft CS requirements

## Playing through the Windows launcher

| Requirement | Details |
| --- | --- |
| Operating system | Windows 10/11 x64, with .NET Framework 4.x and Windows PowerShell 5.1 available. The launcher is x64; the supported Warcraft runtime and mod are x86. |
| Warcraft III | Your own complete **Warcraft III 1.26a** installation; `Game.dll` must report **1.26.0.6401**. Reforged and other patches are unsupported. |
| Counter-Strike | Your own installed **Counter-Strike 1.6**, with the loose models and sounds listed below. Select `cstrike` or its Half-Life parent in the launcher. |
| Graphics/input | A working OpenGL driver compatible with Warcraft's OpenGL mode, a keyboard and a mouse. A wheel is optional; keys 1–7 also select weapons. |
| Installation folder | A dedicated writable folder outside both original games. Allow room for another complete Warcraft copy, converted assets, source revisions and dependency caches. |
| Disk/network | Initial setup and release updates need internet access. Missing Microsoft tools/SDK can require several GB; actual space also depends on the owned game copy. Installed single-player gameplay works offline. |
| Permissions | Accept the launcher's download/install agreement. Microsoft tool installation may request administrator approval or a Windows restart. |
| Game mode | Offline single player, with a living owned unit or hero to control. Complete campaign and custom-map compatibility is still being tested. |

The launcher contains project source/code. Game files, maps, saves, models, sounds and proprietary audio codecs are supplied locally by their owner.

## Required Warcraft files

Select the game root containing:

- `war3.exe`, `Game.dll`, `Mss32.dll`, `Storm.dll`.
- `War3.mpq`, `War3x.mpq`, `War3Patch.mpq`, `War3xlocal.mpq`.
- The complete `redist/miles` folder, including `Mssfast.m3d`, `Mp3dec.asi`, `Reverb3.flt`.
- The runtime's other required supporting DLLs/manifests. Keep the original installation complete.

The original folder is read locally. Setup creates a separate marked Warcraft copy, including its audio providers.

## Required Counter-Strike files

Inside `cstrike`, retain:

- `models/v_ak47.mdl`, `v_m4a1.mdl`, `v_usp.mdl`, `v_awp.mdl`, `v_knife.mdl`, `v_c4.mdl`.
- `sound/weapons` and `sound/player`, including `weapons/knife_slash1.wav` and `player/pl_step1.wav`.

Conversion reads the owned models, hands, animation and audio locally. The original greatsword geometry is generated by the project. An optional owner-selected private sword model must remain available at its remembered path for future updates; it is not downloaded or distributed.

## Dependencies prepared by the launcher

| Dependency | Required capability |
| --- | --- |
| Python | Python **3.10–3.14**, with `venv`, `ensurepip` and pip. Reuse a compatible local interpreter; otherwise the launcher installs pinned PSF Python **3.12.10 x64** privately. |
| Microsoft C++ tools | Visual Studio **2022** or Build Tools, with **Desktop development with C++**, MSVC x86/x64 tools and Windows SDK. Existing compatible tools are reused. |
| NumPy | `numpy>=1.26,<3`, installed in the source revision's private Python environment; see [requirements.txt](requirements.txt). |
| MinHook | The pinned **v1.3.4** source revision and SHA256 in [fetch-dependencies.ps1](tools/fetch-dependencies.ps1), built locally for x86. |

Python downloads are checked by SHA256 and publisher signature. Microsoft's bootstrapper signature and MinHook's source checksum are checked. Vendor licenses and project credits are in [NOTICE](NOTICE). The project launcher itself is unsigned.

## Building from source

Install the Python/C++/SDK capabilities above and **Git for Windows** before running `setup.cmd`. Manual setup takes the actual `cstrike` folder. To build the standalone launcher, also keep the Windows .NET Framework C# compiler, .NET Windows Forms and compression/web assemblies available.

Developers run `tools/test-all.ps1` for the C++ rules, `tools/build-launcher.ps1` and `tools/test-launcher.ps1` for the launcher, and `tools/audit_sources.py` before committing or publishing. Native verification scenes are opt-in and excluded from ordinary builds.

## Publishing an automatic update

Set `VERSION` to the new stable `major.minor.patch` version, build the launcher from audited staged source, and create the matching GitHub tag `v<version>` in `YazgulDev/warcraft-cs`.

Attach `WarcraftCSLauncher.exe`, `WarcraftCS-sources.zip` and **`WarcraftCS-update.json`** to that stable release. Upload the manifest last, after its matching packages are available. Also attach the generated EXE checksum, `REQUIREMENTS.md` and `WarcraftCS-<version>-dist.zip` for direct downloads. The updater validates the tag/version and package hashes; drafts and prereleases are skipped.

Users enable the separate automatic-update checkbox while agreeing to downloads. The launcher checks releases on startup; updates require Warcraft to be closed. Existing saves and INI settings are preserved. See [INSTALL.md](INSTALL.md) and the [launcher guide](docs/CLIENT-LAUNCHER.md) for folders, recovery and updates.
