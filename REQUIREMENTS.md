# Warcraft CS requirements

Applies to **0.6.0**. See [Release Notes](docs/RELEASE-0.6.0.md) for changes and
[antivirus troubleshooting](TROUBLESHOOTING.md#antivirus) for unsigned-module detections.

## Playing through the Windows launcher

| Requirement | Details |
| --- | --- |
| Operating system | Windows 10/11 x64, with .NET Framework 4.x and Windows PowerShell 5.1 available. The launcher is x64; the supported Warcraft runtime and mod are x86. |
| Warcraft III | Your own complete **Warcraft III 1.26a** installation; `Game.dll` must report **1.26.0.6401**. Reforged and other patches are unsupported. |
| Counter-Strike | Your own installed **Counter-Strike 1.6**, with the loose models and sounds listed below. Select `cstrike` or its Half-Life parent in the launcher. |
| Graphics/input | A working OpenGL driver compatible with Warcraft's OpenGL mode, a keyboard and a mouse. A wheel is optional; keys 1–7 also select weapons. |
| Installation folder | A dedicated writable folder outside both original games. Allow room for another complete Warcraft copy, converted assets, source revisions and dependency caches. |
| Disk/network | Initial setup and release updates need internet access. Developer mode can need several GB for missing Microsoft tools/SDK; actual space also depends on the owned game copy. Installed single-player gameplay works offline. |
| Permissions | Accept the launcher's download/install agreement. In Developer mode, Microsoft tool installation may request administrator approval or a Windows restart. |
| Game mode | Offline single player, with a living owned unit or hero to control. Complete campaign and custom-map compatibility is still being tested. |

The standard launcher and public ZIPs contain source without prebuilt DLLs. Only the separate
`WarcraftCSLauncher_DLL_Included.exe` contains ready x86 mod modules. Game files, maps, saves,
models, sounds and proprietary audio codecs are supplied locally by their owner.

## Required Warcraft files

Select the game root containing:

- `war3.exe`, `Game.dll`, `Mss32.dll`, `Storm.dll`.
- `War3.mpq`, `War3x.mpq`, `War3Patch.mpq`, `War3xlocal.mpq`.
- The complete `redist/miles` folder, including `Mssfast.m3d`, `Mp3dec.asi`, `Reverb3.flt`.
- The runtime's other required supporting DLLs/manifests. Keep the original installation complete.

The original folder is read locally. Setup creates a separate marked Warcraft copy, including its audio providers.

## Required Counter-Strike files

Inside `cstrike`, retain:

- `models/v_ak47.mdl`, `v_m4a1.mdl`, `v_usp.mdl`, `v_awp.mdl`, `v_knife.mdl`, `v_c4.mdl`.
- `sound/weapons` and `sound/player`, including `weapons/knife_slash1.wav` and `player/pl_step1.wav`.

Conversion reads the owned models, hands, animation and audio locally. The original greatsword geometry is generated by the project. An optional owner-selected private sword model must remain available at its remembered path for future updates; it is not downloaded or distributed.

## Player and Developer installation

| Button | Behavior | Microsoft tools |
| --- | --- | --- |
| Install (standard EXE) | Builds the modules from source and obtains pinned MinHook; converts owned assets. | Reuses compatible Visual Studio/SDK, otherwise prepares Build Tools/SDK after consent. |
| Install — Player (DLL-included EXE) | Installs bundled `WarcraftCS.mix` and the project-generated `Mss32.dll` loader; converts owned assets. | No Build Tools or Windows SDK download/install. |
| Install — Developer (DLL-included EXE) | The same local compilation as the standard EXE. | Reuses compatible tools or prepares missing tools after consent. |

**Update** is a separate action fetching the latest stable GitHub project release. The standard variant always
builds locally; the DLL-included variant preserves its saved Player/Developer mode and its EXE variant.

Both modes use Python/NumPy for asset conversion. Player validates the owned Miles library against the binary package; a different Miles ABI requires Developer mode. Proprietary Warcraft libraries/codecs remain locally supplied.

## Dependencies prepared by the launcher

| Dependency | Required capability |
| --- | --- |
| Python | Python **3.10–3.14**, with `venv`, `ensurepip` and pip. Reuse a compatible local interpreter; otherwise the launcher installs pinned PSF Python **3.12.10 x64** privately. |
| Microsoft C++ tools (Developer only) | Visual Studio **2022** or Build Tools, with **Desktop development with C++**, MSVC x86/x64 tools and Windows SDK. Existing compatible tools are reused. |
| NumPy | `numpy>=1.26,<3`, installed in the source revision's private Python environment; see [requirements.txt](requirements.txt). |
| MinHook (Developer source build) | The pinned **v1.3.4** source revision and SHA256 in [fetch-dependencies.ps1](tools/fetch-dependencies.ps1), built locally for x86. |

Python downloads are checked by SHA256 and publisher signature. Microsoft's bootstrapper signature and MinHook's source checksum are checked. Vendor licenses and project credits are in [NOTICE](NOTICE). Player modules statically link MinHook; its notice accompanies the binary package and installed runtime. The project launcher itself is unsigned.

## Building from source

Install the Python/C++/SDK capabilities above and **Git for Windows** before running `setup.cmd`. Manual setup takes the actual `cstrike` folder. To build the standalone launcher, also supply owned Warcraft III 1.26a for the supported Miles forwarder ABI and keep the Windows .NET Framework C# compiler, .NET Windows Forms and compression/web assemblies available.

Developers run `tools/test-all.ps1` for the C++ rules, `tools/build-launcher.ps1` and `tools/test-launcher.ps1` for the launcher, and `tools/audit_sources.py` before committing or publishing. Native verification scenes are opt-in and excluded from ordinary builds.

## Publishing an automatic update

Set `VERSION` to the new stable `major.minor.patch` version, build the launcher from audited staged source, and create the matching GitHub tag `v<version>` in `YazgulDev/warcraft-cs`.

Attach `WarcraftCSLauncher.exe`, `WarcraftCSLauncher_DLL_Included.exe`, their checksums,
`WarcraftCS-sources.zip`, `REQUIREMENTS.md` and `WarcraftCS-<version>-dist.zip`.
Upload **`WarcraftCS-update.json`** last. Its primary hash describes the source-only EXE; optional
`DllIncludedLauncherSha256` / `DllIncludedRuntimeSha256` describe the separate bundled variant.
Keep `WarcraftCS-runtime.zip` in private build output rather than release assets. Every public ZIP excludes native modules.
The updater validates the tag/version and selected package hashes; drafts and prereleases are skipped.

The launcher automatically checks releases on every startup. A version/release-notes dialog offers
**Update** or **Not now**; confirming accepts the displayed terms and installs while Warcraft is closed.
Install remains an independent embedded-version action. Old 0.5.0 Player clients need a direct download
of the DLL-included EXE to migrate; they never silently switch to downloading compiler tools.
Existing saves and INI settings are preserved. See [INSTALL.md](INSTALL.md) and the [launcher guide](docs/CLIENT-LAUNCHER.md).
